# Data dictionary

`experiment_users.csv` is **fully synthetic**. It is generated by `python -m src.generate_data` with NumPy seed `20250201`. No customer data or third-party dataset is used.

| Column | Type | Definition |
| --- | --- | --- |
| `user_id` | string | Synthetic user identifier; one row per randomized user. |
| `assigned_at` | date | UTC assignment date, 2025-02-01 through 2025-02-14. |
| `variant` | string | `control` or `treatment`; 50/50 Bernoulli assignment. |
| `device` | string | Pre-treatment device category. |
| `acquisition_channel` | string | Pre-treatment acquisition source. |
| `region` | string | Pre-treatment broad region. |
| `customer_tenure` | string | Pre-treatment `new` or `returning` status. |
| `activated_7d` | integer | At least one activation event within seven days of assignment. |
| `paid_14d` | integer | At least one paid conversion within 14 days; primary outcome. |
| `revenue_usd_14d` | decimal | USD revenue within 14 days; zero for non-payers. |
| `support_ticket_14d` | integer | At least one support ticket within 14 days. |
| `app_crash_14d` | integer | At least one observed app crash within 14 days. |

## Generation assumptions

- Every randomized user is retained in the analysis; no user is dropped after assignment.
- Follow-up for all users ends by 2025-02-28. Readout date is 2025-03-01.
- Outcomes depend on pre-treatment attributes plus a programmed average treatment effect. These dependencies are illustrative, not estimated from real users.
- The generator introduces a small crash risk increase to illustrate a realistic conversion-versus-quality tradeoff.
- Revenue is zero-inflated and right-skewed. The analysis uses revenue **per assigned user**, not revenue per payer, for the experiment comparison.
